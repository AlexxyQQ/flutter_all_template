# Platform setup: permissions, backups, network security

## Principle: declare only what your app uses

The template's permission module can request camera, microphone, location, photos,
contacts, calendar, Bluetooth, phone state, activity recognition and notifications.
A real app almost never needs all of them. Every declared permission:

- must be justified to Google Play / App Review (unused ones get apps rejected);
- is visible to users on the store listing;
- widens what an attacker can do if the app is compromised.

**When you start a project, delete every permission you don't use on both platforms**,
and remove the matching `AppPermission`/screen from `lib/core/common/features/permission/`.

---

## Android — `android/app/src/main/AndroidManifest.xml`

Permissions are grouped under a *"Permission module — remove the ones your app doesn't
use"* comment. Removed from the template on purpose:

| Removed | Why / alternative |
|---|---|
| `CALL_PHONE` | Use an `ACTION_DIAL` intent (`url_launcher` `tel:`) — needs no permission |
| `WRITE_CONTACTS`, `WRITE_CALENDAR` | Read-only by default; add back only if you write |
| `BLUETOOTH_ADVERTISE` | Only for apps acting as a BLE peripheral |
| `RECEIVE_BOOT_COMPLETED` | Only needed to restore **scheduled** local notifications after reboot (awesome_notifications). The template doesn't schedule any |
| `ACCESS_BACKGROUND_LOCATION` | Never declared; requires a Play Console declaration |

Plugins merge their own permissions at build time (e.g. `firebase_messaging` adds
`WAKE_LOCK`, `ACCESS_NETWORK_STATE`). Inspect the merged result in
`build/app/intermediates/merged_manifests/release/…/AndroidManifest.xml` and strip
anything unwanted with `tools:node="remove"`.

### Backups

`android:allowBackup="false"` plus `data_extraction_rules.xml` (API 31+) and
`backup_rules.xml` (API ≤ 30) excluding every domain. Tokens, preferences and log files
are never copied to Google Drive or device-to-device transfers. If you want backup of
specific non-sensitive data, enable it and `<include>` only those paths.

### Network security

`res/xml/network_security_config.xml` (main): HTTPS only, system CAs only. The **debug**
source set overrides it to allow cleartext to `10.0.2.2`/`localhost`/`127.0.0.1` and trust
user-installed CAs (for Charles/mitmproxy). Certificate pinning can be added with a
`<domain-config>` + `<pin-set>` (always include a backup pin and an expiration).

### Release hardening

See [`CODE_SIGNING.md`](CODE_SIGNING.md): real signing key, R8 minify + resource
shrinking, Dart obfuscation with `--split-debug-info`. `android/gradle.properties`
requests a 4 GB Gradle heap, which fits standard CI runners.

## iOS — `ios/Runner/Info.plist`

- Purpose strings (`NS*UsageDescription`) are generic placeholders. **Rewrite each one**
  to say exactly why your app needs the data — vague strings are a common rejection.
- Only "When In Use" location is declared. Add `NSLocationAlwaysAndWhenInUseUsageDescription`
  only if you really need background location (and the `location` background mode).
- `UIBackgroundModes` contains only `remote-notification`, which FCM needs to deliver
  data/silent messages. `fetch` was removed (unused). Also enable **Push Notifications**
  and **Background Modes → Remote notifications** in Xcode → Signing & Capabilities.
- `NSLocalNetworkUsageDescription` was removed (the app doesn't browse the local network).
- App Transport Security stays at its strict default (no `NSAllowsArbitraryLoads`).

### permission_handler needs Podfile macros

On iOS, `permission_handler` compiles **out** every permission handler unless you enable
it with a preprocessor macro. If a permission isn't enabled, `request()` returns
`permanentlyDenied` without showing a dialog; if you enable permissions you don't use,
App Review may ask for purpose strings you don't have.

`ios/Podfile` is generated by Flutter on the first `pod install` and isn't tracked in this
repo. After it exists, edit its `post_install` block:

```ruby
post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_ios_build_settings(target)
    target.build_configurations.each do |config|
      config.build_settings['GCC_PREPROCESSOR_DEFINITIONS'] ||= [
        '$(inherited)',
        # Enable ONLY what Info.plist declares and the app requests:
        'PERMISSION_CAMERA=1',
        'PERMISSION_MICROPHONE=1',
        'PERMISSION_LOCATION_WHENINUSE=1',
        'PERMISSION_PHOTOS=1',
        'PERMISSION_NOTIFICATIONS=1',
        'PERMISSION_CONTACTS=1',
        'PERMISSION_EVENTS_FULL_ACCESS=1',
        'PERMISSION_BLUETOOTH=1',
        'PERMISSION_SENSORS=1',
      ]
    end
  end
end
```

Then run `cd ios && pod install`. Keep this list, `Info.plist`, and the Dart permission
module in sync. (Commit your project's `ios/Podfile` once it is customised.)
